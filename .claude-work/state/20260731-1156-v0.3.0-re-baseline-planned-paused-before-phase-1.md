**The re-baseline, in one line:** dbdict stops being a DuckDB-native *data
dictionary* that describes a database, and becomes a **dataspec** that drives
generation — DDL plus client code in jl/py/rs — across five storage targets,
in both directions.

## Key Decisions

Full record with citations in `goal.md`. The ones that reshape the project:

- **Positioning: a swiss-army tool for OR/MS + AI research, not production.**
  This is what makes the rest affordable — no migrations, evolution, access
  control, multi-user, CI gating or scale story. It is also what makes
  *inferred* constraints acceptable in the brown-field path.
- **Two entry points, not a pipeline.** Brown-field (introspect + profile an
  existing db) and green-field (author it, e.g. simulation output) are both
  first-class. The reverse direction is largely a rewiring of existing code:
  `read_schema` plus the five D01–D05 counters already in
  `crates/dbdict-duckdb/src/native.rs` become inferrers when pointed at a
  database with no spec.
- **Five targets: `duckdb` · `ducklake` · `postgres` · `sqlite` · `hdf5`.**
  Driven by a finding, not a preference — DuckDB proved not mature enough
  *specifically with Julia*, so multi-backend is insurance. JLD2 is a Julia
  *driver* for HDF5, not a target; Quack is a DuckDB access mode, not storage.
- **A lingua-franca type vocabulary — 12 scalars**, explicit-width lowercase
  (`bool`, `int8..int64`, `float32/64`, `string`, `date`, `timestamp`,
  `timestamptz`, `decimal(p,s)`). Breaking change → `$version: 0.3.0`.
- **Compounds deferred, for two independent reasons.** No neutral spelling
  exists; and on this stack there is currently nowhere for them to work —
  DuckDB.jl isn't ready, and using them through JLD2 breaks JLD2↔HDF5
  compatibility, which is the property that made HDF5 worth having.
- **`attrdef:` — declared, expandable attributes.** Schema stays closed; the
  closure is authored by the document. Meta-attributes split into *structural*
  (`type`, `mandatory` — closed, dbdict-owned) and *documentary* (open,
  passthrough). Recursion terminates because leaf values have no attributes,
  not because the vocabulary is closed.
- **`languages:` — named language targets.** The (target db, driver) pair
  fully determines the type mapping, so no companion mapping file is needed
  for V1. This *replaces* the earlier "dataspec is language-free" invariant;
  the surviving property is that the spec is free of type *mappings*.
- **Metadata propagates into the outputs** — a `_dbdict_*` table canonical
  plus `COMMENT ON` mirroring `description:` in SQL stores; native key–value
  attributes in HDF5; comments-only by default in generated source.
- **`dummy` is out of scope for v0.3.0** — it exists today but won't survive
  the internal changes. No work on it during this vision.
